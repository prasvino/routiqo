# Single-command journey dispatch

Foreground batch orchestration defaults to five attempts and permits at most ten. It stops immediately on idle, stale, deferred or blocked results; callers must respect durable backoff before another batch. Cancellation prevents the next command, while an already received success is still atomically acknowledged. Storage exceptions propagate. Every command repeats session verification. This bounded primitive creates no timers and is not yet mounted to foreground/reconnect events.

Explicit web recovery verifies the current server session before releasing only an authentication block for that account. It does not send immediately, clear conflicts or discard rejected work. A failed verification leaves storage untouched. Every subsequent send still verifies the account again, including after claiming, so a session switch cannot reuse a prior recovery decision.

Dispatch one durable leased head at a time through an injected transport. Check the verified active account before claiming and immediately before sending. The HTTP transport must send X-Routiqo-Account; the server compares it with the authenticated cookie, so an account switch between client checks and the request cannot misattribute a command. The header is a consistency check, never an authentication mechanism.

Use fresh UUID leases, existing FIFO/backoff and atomic snapshot acknowledgement. Network/timeout/5xx/429 outcomes defer;401/403 block for session restoration;409 blocks for reconciliation;other4xx reject. Malformed successful responses defer and never remove work. Only actual validated success can save a snapshot and acknowledge. Persistence failures propagate and leave the durable lease for later recovery. No network call inside a database transaction. No automatic command discard.

The web adapter now connects the single-command dispatcher to IndexedDB, verified browser sessions and same-origin transport. Concurrent callers claim through serialized IndexedDB transactions; only the winning lease sends. Retry settlement uses randomized jitter. Importing the adapter performs no work. Authentication blocks require explicit verified restoration; conflicts remain blocked for reconciliation. A background loop and live journey controls are not mounted. Native secure credential transport remains a prerequisite for native dispatch. Tests cover competing browser callers, account mismatch and durable authentication blocks using synthetic HTTP and IndexedDB; no real user account or external network is used.
