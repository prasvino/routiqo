# Browser journal drafts and confirmed snapshots

## Explicit conflict recovery

After a conflict, a user may review the latest confirmed account journal and choose to discard the device draft. Require an in-dialog confirmation explaining that the device draft and current unsaved edits will be removed; do not send a server write. Atomically compare the expected local mutation ID and the exact reviewed confirmed journal against current storage before deleting the draft. Reject changed/missing drafts, changed confirmed versions/content, retired accounts and transaction failures without modifying data. On success return the confirmed journal and replace the editor fields with it. On failure retain editor text and the draft. No automatic merge, rebase or overwrite. Ordinary Save to account remains an explicit subsequent action.

Applicable threats: T02 account isolation, T10 plain-text rendering, T12 private cache/UI leakage, T13 reordered/concurrent actions, T19 deletion resurrection and T20 authoritative server version conflicts. Review local CAS with two tabs and deletion races. Root owns residual risk; authenticated browser/device navigation QA remains a release prerequisite.

Use a dedicated IndexedDB database `routiqo-journal-v1`, account-keyed records, strict read/write transactions and bounded open timeout. One record contains version1/accountId, up to20 durable drafts and up to20 confirmed TripJournal snapshots. Bound serialized UTF-8 size to1MiB. Validate every stored read; reject corruption, unsupported versions and account mismatch without resetting data. Ordinary logout preserves this partition. Planning backups exclude it.

A BrowserJournalDraft is a validated TripJournalWrite plus journeyId. Each content change uses a new mutationId, but a network retry reuses the exact saved draft. Draft save takes an expected previous local mutationId (null for absent) and rejects mismatch atomically, preventing silent cross-tab overwrites. Require a confirmed eligible trip snapshot for that journey before creating/editing a draft. Do not modify supplied base version automatically. Capacity errors preserve all existing drafts; never evict unsent text.

Cache confirmed API journals after runtime validation. Versions never regress; a same-version content mismatch or changed lifecycle metadata fails closed. Keep at most20 snapshots and do not evict a journey with an unsent draft; if no safe slot remains, fail rather than discard work. Incoming API data must not clear or rebase drafts. Acknowledgement takes account, journeyId, expected mutationId and response; only an exact still-current draft may atomically update the confirmed snapshot and remove that draft. Require matching journey/title/notes and response version=expectedVersion+1. A late acknowledgement for a replaced draft returns false and changes nothing.

Retire the account partition on confirmed account deletion by replacing all content with an opaque retired marker. All subsequent operations reject this marker, including late fetch/cache/write/ack attempts; retirement is idempotent. Wire this cleanup alongside the existing journey partition cleanup and retain an actionable notice if local cleanup fails. No synchronous browser storage and no hidden background dispatch. No actual user content in tests.

Acceptance: reopen after draft save; same-account cross-tab compare-and-set conflict; account isolation; acknowledgement rollback/mismatch; stale acknowledgement cannot discard newer text; newer snapshot does not rebase drafts; capacity and corruption fail closed; retirement prevents resurrection. Future UI must display local-save failures, unsent state, server conflicts and explicit retry/review. This storage layer does not imply working native/offline journal UI.

Initial editor design: existing native Modal, plain labelled title/notes fields and existing action tokens. Visual thesis: a quiet writing surface with lifecycle context and clear save status; no additional card grid or decorative imagery. Content: trip dates, personal title/notes, local-vs-account save state and actions. Interaction: normal focus/hover transitions and existing modal focus restoration; no ornamental motion. Explicit Save draft keeps text on this device; Save to account first durably saves the same mutation before network transmission. Label in-memory changes as unsaved, warn before closing/discarding them, and register beforeunload while dirty. If offline, allow local draft save when a confirmed cached eligible trip is available. Failures never clear authored text. Pending server retry reuses the saved mutation. A409 preserves the draft and offers a read-only latest-server review without automatic rebase or overwrite; conflict resolution is a later explicit action. No commute editor. Account/journey changes remount and abort the editor, preventing stale private content from remaining visible.
