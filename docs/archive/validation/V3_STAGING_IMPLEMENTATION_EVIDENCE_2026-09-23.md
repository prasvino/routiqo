## Demonstrable slice

V23 stores fresh purpose-bound traffic candidates, exact request identity and a daily successful-submission debit. Owned Share, Stop and account recovery use browser session/account/CSRF guards; Stop remains available after journey completion. V24 stores one catalog-versioned canonical terminal decision per anchor/five-minute window, including `NO_OUTPUT`, and an independently expiring projection. The bounded PostgreSQL publisher takes session advisory ownership before its `REPEATABLE READ` snapshot, obtains database evaluation time in its first snapshot statement, and applies the provisional 12 accounts/10 agreeing/80% rule. Late or uncommitted candidates cannot reopen a terminal window. Current owned-journey readers receive relevant coarse moments only; reporting uses an opaque visible reference. Internal grant-gated suppression is audited separately from the terminal decision. Independent maintenance removes expired candidate, projection, debit, report and suppression-audit rows while preserving decision tombstones.

The active-journey web surface mounts deliberate Share, exact retry, owner recovery, future-sharing Stop, a community-only canonical list and report controls under its own default-off flag. It distinguishes community reports from official alerts and says accepted candidates are only considered, not necessarily published. OpenAPI and generated TypeScript contracts cover the new transport. [Staging configuration and rollback](../development/LOCAL_SETUP.md#v3-community-traffic-staging-evaluation-adr-0055) name the separate API, publisher, maintenance and web flags; every example is false.

## Subsequent V3 moderator staging slice

ADR 0056 adds a separately flagged admin origin, Google audience, challenge, short session and cookie namespace. Every queue read and review action checks an existing enabled account and a current finite `traffic_review` or `traffic_suppress` database grant. The bounded queue groups canonical reports without reporter or contributor identity, records minimized read audits and shows `EVIDENCE_UNAVAILABLE` when the projection is gone. Dismissal and suppression require current investigable evidence and commit disposition, effect and audit together; a later report reopens a dismissed group. Report intake serializes with review and projection deletion. The admin proxy and UI support no-store reads, exact retry of uncertain writes, unavailable evidence and default-off rendering. V25 adds the database state and bounded cleanup. See the [moderator runbook](../development/V3_MODERATOR_STAGING_RUNBOOK.md).

The full workspace `pnpm check` passed **594 tests / 70 files**, including eight admin client/proxy tests, generated-contract drift, formatting, TypeScript and lint. The admin production build and secret scan passed. A temporary browser fixture exercised desktop and 320 px queue layouts, unavailable evidence, suppression failure followed by exact retry, dismissal and empty pagination; it was removed before the production build. The browser pass did not use real Google OAuth, finite operational grants or a regional road catalog. Independent adversarial review of report/review races, origin isolation, expired sessions and queue bounds found issues that were corrected and re-reviewed without a remaining issue in that scope.

## Subsequent V3 operator grant administration slice

ADR 0057 adds a separately disabled grant-administrator boundary. A named out-of-band `traffic_grant_admin` trust root can administer only short-lived `traffic_review` and `traffic_suppress` grants for exact existing account UUIDs. The admin API and panel have no account directory, root-grant issuance or self-grant path. Grant changes require current session and root authority before and after account/grant locks, use PostgreSQL time, and atomically write minimized 30-day audits. Exact retained retries cannot renew a grant; active grants require explicit revocation before reissue. A separately disabled bounded job cleans expired grants and audit rows. The [grant runbook](../development/V3_OPERATOR_GRANTS_STAGING_RUNBOOK.md) records bootstrap, trial and rollback prerequisites.

Focused PostgreSQL/HTTP tests passed **42 cases**, including uniform target denial for moderator-only sessions, exact retry after root expiry/revocation, actual audit-insert rollback, capacity, and both moderator queue/action versus grant-revocation orders. The subsequent full `:core-api:check` passed **542 Java tests / 88 suites**, zero failures, errors or skips. Full `pnpm check` passed **598 TypeScript tests / 71 files**, generated-contract drift, formatting, typecheck and lint. The admin production build and secret scan passed. A rendered Chrome pass with a temporary mock upstream inspected the grant panel at desktop and 320 px, including empty/current grant states; the temporary fixture was removed. An independent adversarial review found target enumeration, queue lock order, clock consistency and expiry-rendering defects; all were corrected and re-reviewed with no remaining concrete finding in that scope. Real Google OAuth/MFA, root bootstrap, operator trial, regional data and production review were not performed.

## Synthetic utility, not pilot evidence

The deterministic [utility exploration](V3_COMMUNITY_UTILITY_2026-09-23.md) ran 10,000 synthetic windows per scenario. At 8 accounts/window it produced **0%** visible summaries; at 12 accounts with independently 90%-correct reports, **89.00%**; at 25 accounts with 65%-correct reports, **8.49%**. Ten coordinated false accounts among 12 produced **100% wrong visible summaries** in that model. With 15 repeat commuters and a 12-success daily cap, only the first 12 of 24 attempted windows can reach the 12-account floor. These are model outputs, not local road density, accuracy, output latency, privacy protection or production readiness.
