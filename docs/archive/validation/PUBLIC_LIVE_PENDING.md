## Blocking design decision for the selected research path

- [ ] Independently approve or reject the ADR 0054 protocol and ADR 0053 person-level DP claim after full implementation review and utility evidence. The isolated 64-bit capped sparse sampler passes focused tests and has a candidate whole-pilot add/remove bound of `(ε=ln 2, δ≤1/3,145,728 + 3K·2^-63)` for `K≤345,600`, only if one verified person contributes to one key across the entire 30-day pilot and every observable channel respects the bound. V21 has a durable total claim; independent code review accepted the disconnected V22 internal foundation after two fixes. No public publisher/reader or real-density utility evidence exists. At threshold 22, 10 agreeing reports select with probability about 0.016% and 12 with about 0.065%; the old 12/10 utility target is incompatible with this candidate.
- [x] Select irreversible successful Share as the implementation direction; the user authorized proceeding on 2026-09-23. ADR 0054 proposes this input boundary because a later cutoff cannot be reconstructed safely and lock-based deadline misses can be person-dependent. This is not protocol or release approval.
- [ ] Approve exact disclosure and retention for that direction. Current V18 intent Stop, browser copy, account-deletion cascade and immediate-suppression requirements contradict it. No legacy ACTIVE intent may be migrated into a frozen input. User-facing V2 Share must stay disabled until versioned API/client behavior and legal/product review agree.
- [x] Resolve the policy choice after ADR 0052's rejection: the user chose a measurable person-level privacy guarantee. ADR 0053 is the proposed route. ADR 0052 remains rejected because it lacked a bound on membership inference, repeated releases and the complete observable transcript.
- [ ] Approve a transcript-level privacy protocol that defines the protected person-level fact, adversary knowledge, permitted inference, and disclosure claim. ADR 0051's 12-person/10-agreement candidate was rejected: contributor-dependent withdrawal, Ghost Mode, journey completion, deletion or restriction can make an already visible row disappear and reveal participation. Review pre-publication interventions, repeated windows/categories/anchors, block changes, stale clients and all response metadata. Record independent adversarial approval in a new ADR before enabling output.
- [ ] Review the proposed no-retraction rule for a committed input and published aggregate, including Stop, Ghost Mode, journey completion, deletion, verification and moderation actions. ADR 0054 records the proposed ordering; it is not active. A source-dependent suppression or exceptional shutdown would reopen the participation oracle. Never silently implement the candidate as a release.
