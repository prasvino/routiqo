# Traveller-derived public LIVE implementation contract

This document describes the unapproved ADR 0053/0054 person-level research path, now paused with its code and documentation preserved. The user authorized implementation and staging evaluation of the separate [ADR 0055](../../../adr/0055-consented-community-traffic-summary-proposal.md) and [V3 community-summary spec](COMMUNITY_TRAFFIC_SUMMARY_SPEC.md) behind a disabled production flag. V3's different privacy and withdrawal contract has not been accepted for production; do not combine its account/window rule or deterministic threshold with the DP pilot.

Status: public output blocked pending ADR 0054's full protocol review, ADR 0053's whole-pilot person-level privacy review and utility evidence. The user selected final explicit Share as the implementation direction; the current V18 mutable intent/Stop is not that Share. ADR 0051 and ADR 0052 were rejected. Durable human-verification, explicit per-signal private share intent, owner-only Stop/recovery transport, a disconnected private window evaluator, an isolated privacy sampler, a one-person/pilot claim and an internal V22 frozen Share foundation exist. V22 has no endpoint, flag or publisher. No traveller-derived public read API or Live Moment UI is enabled. The separately gated NDMA provider list remains independent.

The private intent service is wired with persistence, browser-auth, routing and the existing curated anchor resolver flag. Its browser transport and share command require separate default-off flags; owner recovery and Stop remain available when new sharing is disabled. The person/window reservation survives account deletion with a 24-hour logical expiry. A separate default-off maintenance job can physically remove expired private records; operational activation and monitoring remain pending.

## Acceptance

- A user must explicitly opt in one accepted private Quick Signal for public consideration after reading a purpose-specific disclosure. This is one command, not a standing consent or an automatic retry. Withdrawal/Stop is available even after private sharing is disabled or the journey ends.
- The server requires current authenticated account, owned active journey at share time, active private receipt and context, current curated catalog, unexpired verified-person authority, no restriction and a fresh explicit intent. Exactly one effective share per person/anchor/category/fixed five-minute window is enforced in PostgreSQL. No raw identity material enters signal or publication tables.
- The private consumed grant must still be retained and its restriction revision must equal the current revision; restriction followed by restoration cannot qualify an older receipt. Missing grant denies rather than assuming the receipt is eligible.
- A versioned V2 Share must atomically freeze one minimal canonical input and enforce ADR 0053's one nonrefundable person contribution across the entire fixed pilot. The current V18 intent is not a frozen input. A durable publisher must apply the proposed sparse geometric release at most once to the complete precommitted key universe and freeze even empty decisions. It produces at most one canonical coarse value per curated anchor/window. It never publishes member lists, counts, raw timestamps, account or receipt identifiers, exact GPS, precise endpoints or individual presence.
- Reads require current owned active journey and relevant context plus a shared rate control. Every reader sees the same canonical result. Under ADR 0054, source authority is resolved at the final successful V2 Share commit; later Stop or Ghost Mode cannot retract that input or alter released aggregate bytes. The exact Share/window seal rule and source-independent failure behavior remain unresolved P1 gates. Before rollout the consent disclosure and current immediate-suppression contract must be revised to state this plainly. A denial, block or exceptional suppression cannot become a source-dependent presence oracle.
- The browser keeps rows only in memory, refreshes in the foreground, expires old rows, marks offline copies stale and clears traveller rows on account switch, Ghost Mode or journey completion. Loading, no recent information, conflict/suppression, unavailable and offline states are truthful and separate from official alerts.
- A moment report refers only to a server-issued authorized moment reference, with a fixed reason and idempotency key. An operator can investigate under strong permissions and bounded retention without a public contributor directory. Abuse, replay, concurrency, withdrawal and stale-cache tests are required.

## Release gates

No public output may be enabled until ADR 0054's Share/seal and delivery protocol and ADR 0053's entire observable transcript, person-level bound, noise implementation and operational failure behavior receive independent adversarial approval. Threshold 22 makes publication with 10–12 agreeing travellers exceptionally rare; real consented density and factual-accuracy evidence must justify the utility. Review colluding verified people, known-neighbor evidence, repeated routes/windows, block toggles, account deletion, stale clients, retries, multi-replica races and moderator actions. Real identity-review operations, OAuth, curated Chennai/OMR catalog, staging load/retention, accessibility and device QA remain separate gates. Keep the endpoint closed when any authority is unavailable.
